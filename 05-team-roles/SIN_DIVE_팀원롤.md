## 3. 공동 작업 영역

담당이 갈리지 않는 부분은 **먼저 필요한 쪽이 만들고 규칙으로 경계를 지켰습니다.**

| 영역 | 내용 | 경계 유지 방법 |
|------|------|---------------|
| 전투 코어 | 데미지·쿨다운·게이지 규칙 | 싱글 · PvP 양쪽이 같은 코어를 씁니다 |
| UI 컴포넌트 | 스킬바, 전장, 토스트, 카드함 | 모드별 차이는 인자로 주입합니다 |
| 아트 디렉션 | 도트 그래픽 규칙, 팔레트 | 명세 문서(`docs/specs/`)가 기준입니다 |
| 경계 검사 | 모드 간 의존 방향 | `npm run check:boundaries`가 **코드로 막습니다** |

마지막 줄이 중요합니다. 3인이 병렬로 작업하면 **싱글 코드가 PvP를 직접 참조하는
사고**가 반드시 생깁니다. 사람이 기억하는 규칙은 지켜지지 않으므로 검사 스크립트로
막았습니다.

## 4. 협업 방식 — AI-DLC 기반

세부 내용은 **[04. AI 활용 기술 문서](../04-ai-tech-doc/)**에 정리했습니다.

| 단계 | 누가 | 무엇을 |
|------|------|--------|
| Inception | Peter 주도 | 설계 문서를 작성하고 승인합니다. 코드보다 문서가 먼저입니다 |
| Construction | 정호 · 연욱 | 각 담당 영역을 구현합니다. AI가 코드, 사람이 판정 |
| Operations | 연욱 | 브랜치 → PR → 머지 → 배포. 신고받은 날 배포합니다 |

**결정 게이트는 담당 영역의 사람이 쥡니다.** "AUTO를 끄면 데미지까지 멈추는가" 같은
질문은 코드로 유도할 수 없어서, 그 영역 담당자가 판정하고 근거를 코드 주석에
남겼습니다.
